3. Flujo de datos

1
Candidato llena formulario y sube INE + CV
2
Frontend sube archivos a buckets ines y cvs (storage)
3
Storage devuelve URLs públicas
4
Candidato responde 12 preguntas psicométricas (90s c/u, autoavance)
5
Candidato responde evaluación técnica del puesto
6
Sistema calcula puntaje y veredicto: ≥70% Apto · 50-69% Adicional · <50% No cumple
7
INSERT en tabla "Formulario de Candidatos" con todo: datos, URLs, respuestas, puntaje
8
Dashboard RH lee la tabla y muestra el expediente completo

5. Almacenamiento de archivos

Dos buckets públicos: ines (jpg/png) y cvs (jpg/png/pdf). Límite 10 MB por archivo.

Convención de nombres

{nombre_slugificado}_{timestamp}.{ext} — ej: juan_perez_1730000000000.png

6. Seguridad y validaciones

  • Anon key: solo permite las operaciones permitidas por RLS — no es un secreto.
  • Sanitización: nombres se filtran de <>"'`\ antes de guardar (ver ma-baker-validators.js).
  • Rangos numéricos: edad 18-65, estatura 1.40-2.20, peso 40-200, archivo ≤10MB.
  • Tipos MIME: solo imágenes y PDF en uploads.
  • Mejoras futuras: agregar auth para Dashboard RH, restringir SELECT con RLS por rol.

7. Despliegue y mantenimiento

Distribución

  • Formulario candidatos: hospedar el HTML en cualquier servidor estático (Netlify, Vercel, GitHub Pages) y compartir el link.
  • Dashboard RH: solo para uso interno; subir a un sitio protegido o abrir como archivo local.

Tareas periódicas recomendadas

  • 📅 Semanal: ejecutar Suite de Pruebas para verificar que todo sigue funcionando.
  • 📅 Mensual: descargar Backup completo desde el Sistema de Backups.
  • 📅 Trimestral: revisar logs (MaBakerLogger.export()) y limpiar datos antiguos si es necesario.
